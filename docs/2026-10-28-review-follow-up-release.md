# 二次复审问题收尾与发布计划

日期：2026-10-28。用户已批准迭代、commit / push、先发布已获批版本，再送审新版本。范围仅覆盖 [二次复审](2026-10-28-post-iteration-review.md) 的三个已确认问题；复用现有 main，不派发新 agent。

## 模块与接口

- `options.js`：在异步读取完成、即将同步重绘时记录当前焦点的列表区域、条目 ID 和操作。重绘后仅在原节点被移除且浏览器回落到 body 时恢复；同 ID 的收藏/最近分别定位。删除时落到相邻条目，空列表落到该区域标题。等待期间用户已移到其他区域时不抢焦点。
- `gallery/companion.js`：冷首载复用现有 `setLoading / Session.busy`、status 和 revision，立即显示准备状态；覆盖内容和画作准备。成功、失败、关闭、禁用及迟到结果均遵守当前请求生命周期。键盘可收起，自动展示继续保留宿主输入焦点。
- 选择提示使用既有 `reading_selection_v2` 表达“上次选择”，仍可再次选择；不再把持久历史标记解释为“下次打开”。沿用既有一次消费与当前内容保留行为，不引入跨标签确认协议或存储迁移。
- 开发夹具补齐生产后台状态存储通知，并提供通过生产后台进行本地 reading 操作的验证路径；夹具不进入发布包。
- ArtBreeze 版本 1.2.2，WaitWiki 版本 1.4.2。权限、站点范围、Art 24 背景、Wiki 单一可关闭 bg-027、透明正文、默认时长和内容类别保持已确认设计。

## 验收与交付

1. 收藏/最近选择后焦点仍在同一区域、同条目、同操作；下一次 Tab 连续；删除、空列表、慢读取期间主动移走焦点均有回归。
2. 两款指针/键盘冷首载立即显示可播报准备状态；成功清理、失败可重试；关闭或新请求使迟到结果失效，不抢 AI 输入焦点。
3. 选择 A、打开 A、换 B、关闭重开 B 后，设置页不再承诺“下次打开 A”；重选 A 仍生效。
4. 两仓完整构建与必要浏览器视觉/交互验证通过，核对 ZIP 内源文件、版本、24/1 资源与权限。
5. 实现、验证及发布包摘要写入 docs，commit / push。后台先手动发布已获批的 1.2.0 / 1.4.0，确认发布结果后上传 1.2.2 / 1.4.2 并提交审核，沿用审核通过后手动发布偏好。记录实际后台状态，不以点击动作代替提交成功证据。
